# BASHT × Daftra — دليل الإطلاق على Railway (iPhone فقط) · Rollout runbook

**الحالة / Status:** تصميم وكود واختبارات وCI **فقط**. لم يُنشر شيء، ولم يُغيَّر أي متغير أو سرّ أو خدمة في Railway، ولم تُرسل أي طلبات حقيقية إلى Daftra، ولم يُمَسّ OpenClaw Gateway أو النموذج أو volume `/data`.
كل خطوة في هذا الدليل **تنتظر موافقتك الصريحة** (القسم 9). لا تحتاج أي خطوة shell: كلها من Safari / تطبيق Railway / تطبيق Passwords.

المراجع التقنية: `docs/DAFTRA_RAILWAY_SERVICE_NOTES.md` (التصميم + نموذج التهديدات + خريطة الاختبارات) · `docs/DAFTRA_PACKAGING_NOTES.md` (الملفات والفحوص) · `docs/DAFTRA_INTEGRATION_CONTRACT.md` (عقد Daftra).

## 1. لماذا خدمة منفصلة، ولماذا «لا مفتاح Daftra عند الوكيل»

1. **أدوار مفتاح Daftra على مستوى الكيان لا الطريقة** (Only Allow / Only Block على كيانات مثل `invoice` و`client`؛ لا فرق بين GET وPOST — `docs.daftara.dev/933385m0`). أي مفتاح يقرأ الفواتير يستطيع أيضًا إنشاءها. لذلك **لا يوجد «مفتاح قراءة» آمن**: وكيل يملك أي مفتاح Daftra يتجاوز الـ broker بطلب مباشر.
2. لذا في وضع الخدمة: **الوكيل لا يملك أي بيانات اعتماد لـ Daftra**. كل قراءاته تمرّ عبر الـ broker (GET فقط، قائمة بيضاء، بمفتاح الـ broker)، وكل الكتابة تنتظر موافقتك أنت من متصفح جوالك.
3. **الـ broker خدمة Railway ثانية** بحاويتها ومتغيراتها وvolume خاص بها؛ الوكيل (خدمة OpenClaw) لا يقرأ بيئتها ولا ملفاتها ولا `/proc` الخاص بها، ولا يملك أي رمز Railway.
4. **الموافقة من قناة مستقلة**: لوحة المشغّل (دومين عام محمي) بكلمة مرور + رمز TOTP يُدخَل لكل عملية؛ لا توجد عبارة موافقة يراها الوكيل ولا مسار `execute` للوكيل أصلًا.

```
 iPhone (أنت) ──https──► لوحة المشغّل (PORT 8080، دومين عام) ┐
                                                              ├─ خدمة basht-broker (volume /broker-data خاص)
 خدمة openclaw (الوكيل) ──http──► basht-broker.railway.internal:8081 ┘   ──https──► <tenant>.daftra.com
   (لا مفتاح Daftra، لا سرّ موافقة)                                        (المفتاح الوحيد + الكتابة هنا فقط)
```

## 2. ما الذي تغيّر في الريبو (لن يُطبَّق حتى تدمج وتنشر)

| الملف | الأثر |
| --- | --- |
| `Dockerfile` + `entrypoint.sh` + `skill-sync.sh` (OpenClaw) | خط عربي (`fonts-noto-core`) + نسخ المهارة إلى `/data/workspace/skills/basht-daftra` عند الإقلاع. سطر الإقلاع و`chown` وحزمة OpenClaw 2026.10.9 **لم تتغير**؛ فشل المزامنة لا يوقف الـ Gateway |
| `Dockerfile.broker` + `broker-entrypoint.sh` | صورة صغيرة للـ broker فقط (بدون OpenClaw/Chromium/Python/curl)، مستخدم غير جذري `broker`، healthcheck `/healthz` |
| `.github/workflows/basht-daftra-ci.yml` | 6 فحوص: اختبارات على Node 24 و26، فحوص Dockerfile، بناء صورة الـ broker + smoke، اختبار PDF العربي، أهلية المهارة مع OpenClaw المثبَّت |
| `railway.broker.toml` | مرجع اختياري فقط (Config-as-code مُهمَل عند Railway حتى 2026-12-01) — **لا يُعتمد عليه** |

**دمج هذا الفرع ثم إعادة نشر خدمة `openclaw` يطبّق تغييرات Dockerfile/entrypoint على الإنتاج** — وهذا قرار منفصل يحتاج موافقتك (القسم 9).

## 3. الإعداد على iPhone — خطوة بخطوة (بعد موافقتك)

> أسماء الأزرار في Railway قد تختلف قليلًا عن الوصف؛ كل خطوة تُراجَع بالعين مرة واحدة. استخدم **تطبيق Railway** أو Safari على لوحة Railway.

### 3.1 خدمة الـ broker (جديدة)
1. **New Service → GitHub Repo** → هذا المستودع، الفرع `feat/basht-daftra-readonly-pdf` (أو `main` بعد الدمج). سمِّ الخدمة **`basht-broker`** بالضبط (اسم DNS الخاص مشتق منه: `basht-broker.railway.internal`). لا تربطها بـ volume خدمة OpenClaw.
2. **قبل أول نشر**: أضف المتغير `RAILWAY_DOCKERFILE_PATH` = `Dockerfile.broker` (وإلا ستبني Railway الـ Dockerfile الجذري = نسخة OpenClaw ثانية).
3. **Volume**: أضف volume جديدًا للخدمة، مسار الربط `/broker-data` (لكل خدمة volume واحد).
4. **المتغيرات** (الصقها من مولّد كلمات المرور في تطبيق Passwords: ≥32 حرفًا للأسرار والرموز، ≥20 للكلمة):

| المتغير | القيمة |
| --- | --- |
| `DAFTRA_BASE_URL` | `https://<مستأجرك>.daftra.com` |
| `DAFTRA_WRITE_API_KEY` | مفتاح Daftra **جديد** مخصص للـ broker (القسم 6) |
| `DAFTRA_APPROVAL_SECRET` | نص عشوائي ≥32 |
| `BROKER_AGENT_TOKEN` | نص عشوائي ≥32 (رمز الوكيل) |
| `OPERATOR_PASSWORD` | ≥20 حرفًا |
| `OPERATOR_TOTP_SEED` | نص عشوائي ≥32 (منه يُشتق مفتاح TOTP) |
| `BROKER_TRUST_PROXY` | `1` |
| `OPERATOR_ENROLLMENT` | `1` **مؤقتًا** (يُحذف بعد التسجيل) |
| `BROKER_PUBLIC_ORIGIN` | `https://<دومين الـ broker العام>` (بعد الخطوة 5) |
| `DAFTRA_WRITES_ENABLED` | **اتركه غير مضبوط** (الكتابة مستحيلة) |

5. **Networking**: ولّد دومينًا عامًا للمنفذ **8080 (`PORT`) فقط**. عند ظهور قائمة منافذ اختر 8080. **لا تُنشئ أبدًا دومينًا أو TCP proxy للمنفذ 8081.** (لو اخترت 8081 بالخطأ: الـ API الخاص يرفض الطلبات القادمة عبر الدومين العام ويُظهر إنذارًا أحمر؛ لا يُفتح مسار كتابة.)
6. انشر. افتح `https://<الدومين>/healthz` في Safari ← يظهر `ok`.

### 3.2 تسجيل المصادقة (مرة واحدة)
1. افتح `https://<الدومين>/` وسجّل الدخول بكلمة المرور ← افتح `/enroll`.
2. انسخ **setup key** إلى تطبيق **Passwords** (iOS): Verification Code ← Enter Setup Key (رمز زمني، 6 أرقام، 30 ث).
3. **احذف `OPERATOR_ENROLLMENT`** وأعد نشر الـ broker. بعدها `/enroll` غير موجود.

### 3.3 خدمة الوكيل (openclaw — الموجودة)
أضف **فقط**: `DAFTRA_BASE_URL`، `DAFTRA_BROKER_URL=http://basht-broker.railway.internal:8081`، `DAFTRA_BROKER_TOKEN` (نفس قيمة `BROKER_AGENT_TOKEN`).
**احذف** أي `DAFTRA_API_KEY` أو `DAFTRA_WRITE_API_KEY` أو أي سرّ للـ broker من هذه الخدمة، ولا تُنشئ لها `RAILWAY_API_TOKEN`. لا تستخدم متغيرات مرجعية `${{basht-broker.*}}` لأي شيء سوى الرمز أعلاه.

### 3.4 أول اختبار بعد النشر — قراءة فقط (الكتابة مُعطّلة)
من محادثة الوكيل: `capabilities` ← `broker_mode: service` و`daftra_credentials_on_agent: false`. ثم قائمة التحقق في القسم 7.

## 4. تفعيل الكتابة — لاحقًا ومشروط
لا يحدث إلا بعد اجتياز القسم 7 وبموافقتك: أضف `DAFTRA_WRITES_ENABLED=1` **في خدمة الـ broker فقط**، لجلسة قصيرة مُشرَف عليها، على **مسودات** أولًا. كل عملية: الوكيل يقترح ← تفتح اللوحة وتقرأ المعاينة كاملة ← تنتظر رمزًا **جديدًا** ← «Approve & send». بعد الجلسة أزل المتغير.

## 5. الرجوع Rollback
| الحالة | الإجراء |
| --- | --- |
| مشكلة في الـ broker | أوقف/احذف خدمة `basht-broker` (volume الخاص به فيه مقترحات/دفتر/تدقيق فقط). الكتابة مستحيلة بدونه لأن الوكيل لا يملك مفتاحًا |
| مشكلة بعد دمج Dockerfile/entrypoint | في Railway: Redeploy للنشر السابق لخدمة `openclaw` |
| اشتباه بتسرّب | أوقف الكتابة (احذف `DAFTRA_WRITES_ENABLED`)، دوّر المفاتيح (القسم 6) |

## 6. تدوير المفاتيح والحسابات — **وثّقتُه ولم أبدأه**
1. **مفاتيح Daftra** (`Settings ← API ← API Keys`): إن كان أي مفتاح قد كُشف سابقًا (محادثة/Commit) فاحذفه فورًا. أنشئ **مفتاحًا واحدًا جديدًا** للـ broker بدور **Only Allow** على الكيانات المطلوبة فقط (مثل `invoice`، `client`، `product`، `supplier`، `purchase_invoice`… تحقق من الأسماء الدقيقة للبقية في واجهة Daftra؛ ابدأ بالأقل وأضف عند ظهور 403 — يعرضها الـ broker بوضوح). **لا تُنشئ «مفتاح قراءة» للوكيل**: لا وجود لمفتاح قراءة فقط.
2. **رمز الوكيل `BROKER_AGENT_TOKEN`**: ضع القديم في `BROKER_AGENT_TOKEN_PREVIOUS` والجديد في `BROKER_AGENT_TOKEN`، حدّث `DAFTRA_BROKER_TOKEN` في خدمة الوكيل، أعد نشر الخدمتين، ثم احذف `…_PREVIOUS`.
3. **كلمة المشغّل/TOTP**: غيّر `OPERATOR_PASSWORD` و/أو `OPERATOR_TOTP_SEED` ثم كرّر التسجيل (3.2).
4. **`DAFTRA_APPROVAL_SECRET`**: يوقّع المقترحات والدفتر؛ تغييره يُبطل المقترحات المعلّقة ويكسر التحقق من الدفتر القديم. دوّره فقط عند اشتباه حقيقي، ويكون بإنشاء خدمة/volume جديدين (التاريخ القديم يبقى في نسخ Railway الاحتياطية).
5. **Railway**: راجع أعضاء المشروع، ولا تُصدر رموزًا (Project/Account tokens) للوكيل.

## 7. قائمة اختبار قراءة فقط على Daftra الحقيقي — **لم تُنفَّذ**
(الكتابة مُعطّلة؛ كل بند يُنفَّذ بعد موافقتك)
1. `https://<الدومين>/healthz` = `ok`؛ `/` تعرض صفحة الدخول فقط، بلا أي معلومة عن الإعداد.
2. دخول (كلمة + TOTP)؛ دخول بكلمة خاطئة يُرفض؛ بعد 3 أخطاء متتالية تظهر المهلة.
3. `capabilities` من الوكيل: `broker_mode: service`، لا بيانات اعتماد Daftra عند الوكيل، `writes_enabled: false`.
4. `list invoices --all`: عدد السجلات = العدد في واجهة Daftra (نفس المرشّحات).
5. `report trial_balance` وتقرير آخر: الأرقام تطابق واجهة Daftra.
6. `pdf <رقم فاتورة>`: يُفتح على الـ iPhone ويطابق الأصل (ملف دفترة الرسمي).
7. `export invoices --format xlsx|csv|docx|pdf`: تُفتح الملفات؛ العربي سليم؛ ملف PDF المُولَّد معنون «غير رسمي».
8. `propose` مسودة (مصروف/منتج): تظهر في اللوحة مع شريط «الكتابة معطّلة» وزر الموافقة معطّل؛ `execute` من الوكيل مرفوض.
9. تأكد من عدم ظهور أي سرّ في سجلات Railway لكلا الخدمتين.
10. جرّب (للتأكد من الفشل المغلق): رمز وكيل خاطئ ← 404؛ استدعاء `/v1/*` عبر الدومين العام ← 404.
11. **فقط بعد النجاح التام وبموافقة منفصلة**: جلسة كتابة مُشرَفة على مسودة (القسم 4).

## 8. حدود الأمان المتبقية (مختصرة؛ التفصيل في ملف التصميم)
- كل من يملك وصولًا إلى لوحة Railway/المتغيرات لخدمة الـ broker يقرأ الأسرار (مفتاح الكتابة، سرّ الموافقة، بيانات المشغّل) — قيّد أعضاء المشروع.
- جوال/تطبيق Passwords مخترَق = قدرة موافقة كاملة؛ والموافقة دون قراءة المعاينة تُبطل البوابة.
- رمز الوكيل المسرَّب يقرأ كل ما يقرؤه مفتاح الـ broker (لا يكتب) ويقترح (بحصص). لذلك قيّد أدوار مفتاح الـ broker بالكيانات اللازمة فقط.
- كل خدمة في نفس بيئة Railway تصل إلى الشبكة الخاصة؛ أبقِ البيئة صغيرة.
- شبكة Railway الخاصة plain http مشفّرة بـ WireGuard (لا mTLS إضافي). TOTP من نوع SHA-1 (لا WebAuthn بعد). نسخة واحدة (volume).
- اعتماد تحديد المحاولات بالـ IP على `X-Real-IP` من حافة Railway.

## 9. الموافقات المطلوبة منك قبل أي إطلاق حي (لم يُنفَّذ أي منها)
1. **الدمج** إلى `main`.
2. **إعادة نشر `openclaw`** بالـ Dockerfile/entrypoint الجديدين (خط عربي + نسخ المهارة) — ولها رجوع (القسم 5).
3. **إنشاء خدمة `basht-broker`** + volume + المتغيرات (القسم 3.1) + دومين عام للمنفذ 8080.
4. **تعديل متغيرات خدمة الوكيل** (القسم 3.3) وحذف أي مفتاح Daftra منها.
5. **إنشاء/تدوير مفاتيح Daftra** (القسم 6).
6. **اختبار القراءة الحي** (القسم 7).
7. **تفعيل الكتابة** `DAFTRA_WRITES_ENABLED=1` لجلسة مُشرَفة على مسودات (القسم 4).
